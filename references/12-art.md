# 12 AI 美术制作（Blockbench 模型与贴图）

> 管什么：用 Blockbench（含可编程 MCP 接口）产出方块风模型与贴图时，必须遵守的像素密度、UV、共面、源区取料、分层染色判据，以及工具层操作纪律与验收手法。
> 上游：`SKILL.md`（结论以此为准）；本文件给细节、数值与案例。相关：[13-entities.md](13-entities.md) §13.4（模型 / 判定箱 / 渲染偏移对齐）、[10-troubleshooting.md](10-troubleshooting.md)（闪烁与杂点类症状索引）。

标签：**铁律**（违反即返工）· **实测**（有一手证据）· **推断**（未实测，须先验证）。

## 12.1 像素密度 1:1

**铁律**：1 个模型单位 = 1 个纹理像素（原版方块 16 px）。**每个面的 UV 矩形宽高必须等于该面的实际尺寸**，不许给不同尺寸的面套同一个 UV 矩形。

原理：UV 矩形的宽高决定"这段贴图铺到多大的面上"。矩形小于面 → 每个纹素被拉伸到大于 1 模型单位，像素被拉成条纹；矩形大于面 → 纹素被压缩，细节糊掉。mipmap 与各向异性过滤会把这种比例误差放大成整片脏色，所以比例问题必须在建模阶段解决，不能指望渲染端补救。

面尺寸与矩形公式（设方块 `size = [w, h, d]`，UV 起点 `(u, v)`）：

| 面 | 面的实际尺寸 | UV 矩形 |
|---|---|---|
| `up` / `down` | 宽 × 深（`w × d`） | `[u, v, u+w, v+d]` |
| `east` / `west` | 深 × 高（`d × h`） | `[u, v, u+d, v+h]` |
| `north` / `south` | 宽 × 高（`w × h`） | `[u, v, u+w, v+h]` |

注意 `up` / `down` 用的是**深度**而不是高度：很多"顶面被压扁"的模型就是把 `up` 按 `w × h` 取了矩形。`north` / `south` 与 `east` / `west` 的第二个维度都是高度 `h`，第一个维度分别是宽度与深度，两两成对，容易记混。

两个实测反例（同一类错误的不同表现）：

- 翼膜实体是 6×9（宽×深），UV 却统一给 6×6 → 深度方向被拉伸 1.5 倍，翅膀边缘像素被压缩成锯齿。同一组翼膜里实际存在三种尺寸——`6×9` / `4×8` / `3×6`——被同一个 6×6 矩形套住，三种面各自被压成不同比例，边缘像素压缩程度都不一致。
- 一个 6×5×16 的身体，6 个面共用同一块 UV 矩形 → 身体绿色被拉长成条纹。

判定手法：把 `.bbmodel` 里每个 `cube` 的 `size` 与六个面的 `uv` 一起打印出来，逐面算 `uv` 宽高与面尺寸的比值；比值 ≠ 1 的面就是嫌疑面。**不要只看渲染图**——正交视角下 1.2 倍的拉伸常常看不出来，但在游戏里斜看时非常明显。

允许的例外只有一种：**有意做风格化的比例失真**（例如卡通化的大头）。这时要在注释里写明"此处为刻意 2× 放大"，否则后人会把它当 bug 修掉。

约定：一个部件内的所有面尽量共用同一套纹理布局（同一张图集的不同区域），但**矩形必须逐面按尺寸取**，不要为了省事把六个面塞进一个矩形。

## 12.2 UV 逐面指定与脚本改动纪律

**铁律**：UV 必须逐面指定，模型用 `box_uv = false`。

`box_uv = true`（盒子 UV）时，一个 cube 只有**一个** UV 矩形，六个面按固定规则映射进这块矩形，不同尺寸的面自动共享同一比例；`box_uv = false`（逐面 UV）时，每个面各自带一个 `[x1, y1, x2, y2]` 数组，可以按 §12.1 的公式精确取料。

数据落点（`.bbmodel` 是 JSON）：

```json
"elements": [{
  "from": [0, 0, 0], "to": [6, 9, 2], "box_uv": false,
  "faces": {
    "north": { "uv": [0, 0, 6, 9] },
    "up":    { "uv": [0, 0, 6, 2] }
  }
}]
```

- `uv` 坐标是**贴图像素坐标**，不是 0–1 归一化值；16×16 的图就是 0–16。把 0–1 的值填进去会得到"全部面都采左上角 1 像素"的纯色模型，而且不报错。
- 面的 UV 可以带 `rotation`（0 / 90 / 180 / 270），用于把贴图旋转 90° 贴合纹理走向；改了旋转就相当于改了取料方向，**旋转与宽高不匹配同样会拉伸**。
- 多贴图模型用 `faces.<面>.texture` 指定贴图索引（0 起），不写则默认 0。
- 改 UV 前先 `Undo.initEdit({elements})`，改完 `Undo.finishEdit()`。不包进 undo 事务的修改不会正确进撤销栈，也容易在后续操作里被覆盖。
- 改完立即 `export_model(codec=project)` 存回 `*.bbmodel`。只改内存不落盘，窗口一关模型就"丢了"（实测：这是最高频的资产丢失原因）。

**工程格式陷阱**：工程格式是 `geckolib_model` 时，需要对应 GeckoLib 插件才能重开；环境里没装插件就不要指望 GUI 打开，保留 `.bbmodel` 原件，用脚本转换。

## 12.3 面朝向、法线与内外翻

三个轴与六个面在模型坐标系里是固定映射（Y 向上）：

| 面 | 法线方向 | 说明 |
|---|---|---|
| `north` | `-Z` | 朝向观察者的"前面" |
| `south` | `+Z` | 背面 |
| `east` | `+X` | 右侧 |
| `west` | `-X` | 左侧 |
| `up` | `+Y` | 顶面 |
| `down` | `-Y` | 底面 |

- 一个 cube 的六个面是**朝外**的；要"掏空"内部（例如做空心桶、翅膀中空），不是删面，而是再加一层反向几何或用 `inflate` 做壳。删面会让内壁透空，看到背面剔除后的破洞。
- 需要"贴图只在一侧显示"时，另一侧的面仍然存在，只是被遮挡——不会因为看不见就省掉性能开销。大面积遮挡的面建议直接删，但要确认从任何角度都看不到。
- 面朝向是 §12.4 共面判据的第二个要素；判断共面时**必须带上朝向**，只看坐标会把安全情况误判成问题。

## 12.4 禁止共面（z-fighting）

**铁律**：同一平面上出现两个**朝向相同**且面积重叠的面 → z-fighting 闪烁。

判据三要素，缺一不成立：

1. **同一平面**：两个面在某一个轴上的坐标完全相等（如都在 `z = -2`、都在 `y = 9.8`）。
2. **朝向相同**：法线方向一致（都是 `north`，或都是 `down`）。
3. **面积重叠**：在另外两个轴上的投影区间有交集。

朝向相反的两面共面**不会**闪——背面剔除会去掉其中一个，只剩一面参与深度测试。所以"共面必闪"的说法不成立，**同朝向共面才闪**。（推断：若渲染类型显式关闭了背面剔除，反向共面也可能出问题；默认剔除类型下不闪。）

实测高危组合：

| 组合 | 共面位置 |
|---|---|
| 骨架条 vs 翼膜 | `leading_bone.north` 与 `membrane.north` 同在 `z = -2` |
| 尾部脊条 vs 横条 | 两者的 `down` 面同在 `y = 9.8` |

为什么"贴在一起"必然闪：两个面到相机的距离在数值上相等，深度缓冲无法区分谁在前，光栅化时的浮点误差会让每个像素随机选一个面，逐帧变化就是闪烁。距离差小于深度精度时同样会闪——这就是"留 0.001 也没用"的原因。

修复与判据：

- **各轴外扩**：把骨条在三个轴上分别外扩，使**任意两面之间的最小间距 ≥ 0.02 模型单位**。geo.json 里的对应字段是 cube 的 `inflate`，它把几何沿法线向外推，不改贴图映射。
- **外扩量不要用统一值**：统一外扩会让平行的同类面（例如两条脊条）重新变成共面。用一组互不相同的值（0.02 / 0.03 / 0.04 …）。
- **间隙别取太小**：0.001 这类间隙在几十格外的深度精度下仍会闪，0.02 是可用下限，不是理论上上限。
- **改完必做坐标复查**：遍历所有部件，按"轴 + 坐标 + 朝向"分组，确认组内没有面积重叠项；这是硬证据。

复查脚本的输出要能直接看出问题，例如按组打印 `axis=y value=9.8 facing=down parts=[ridge, crossbar] overlap=true`。只打印坐标不打印朝向的脚本会漏掉一半问题。

## 12.5 贴图源区必须是"纯料"

**铁律**：不要在一个混有透明像素或别的物件颜色的区域里取大矩形 UV。

原版图集是多物件混排的（同一个 PNG 里并排放着不同部位、甚至不同生物的贴图），直接按坐标取矩形很容易串到透明区或相邻物件的颜色。典型症状：

- 翼膜出现深色杂点（UV 矩形越界，采到了透明 / 骨色区域）。
- 骨面发脏（矩形里混进了中性色或描边色）。

两条合规做法：

1. **先探测源区有效边界**：把目标区域逐像素分类打印成字符图，确认矩形内只有一类像素，再指 UV。
2. **自己平铺一块专用区域**：在贴图空白处铺一块纯料区（见 §12.6 的镜像平铺），UV 只指向这块自建区域。需要大面积时这是唯一稳妥做法。

约定：优先引用原版贴图而不是自绘，风格最贴合；但必须同时满足本条与 §12.6。

## 12.6 镜像平铺与源块纯净（竖纹根因）

现象：骨条上出现"梳齿状竖纹"。

两种错误做法及其后果：

- **纯色块填充**：为消接缝把骨料 / 膜料区直接涂成一个纯色 → 细节全毁（整块只剩一个色阶），观感死平。
- **判据过宽的镜像平铺**：改成"从原版图集挑小块镜像平铺"，但挑块判据过宽（把中性色、暗色也算作骨色）→ 膜面出现**绿色杂点**、骨面发脏。

真正的根因：原版 `phantom.png` 第 32 行是

```
...##########obbbbbbbbbboooo...
```

第 25 格是中性色 `o`，第 26–35 格才是纯米色 `b`。骨料块恰好从 `x = 25` 取 9 像素（`o` + 9 个 `b`），于是**每 9 像素重复一次那个 `o` 列 → 竖条纹**。

一般化结论（**实测**）：**一个"几乎纯"的源块，其杂色列会被平铺周期放大成规律条纹。** 纯度不足不是"稍微有点脏"，而是会被周期变成结构化的图案。

由此定下的九条规范：

1. **消接缝用"镜像平铺"**：把源块镜像再拼（周期 = 2× 块宽），交界处像素连续，不会出现硬缝。
2. **源块必须严格纯净**：先按像素分类打印贴图的字符图（`. / B / b / o / # / G`），肉眼确认要取的矩形**全在同一类**，再取。判据宁严勿宽——"骨色"就只接受米色，别把中性色、暗色、描边一起收进来。
3. **镜像平铺的块必须整除目标区**（如 8×2 铺满 32×32）；否则边缘会错位，接缝从"硬缝"变成"错位缝"。
4. **禁止用纯色块填充**替代有细节的区域。可以"平"，但不能"死平"；至少保留原版 2~3 个色阶。
5. **大改前必须备份**：`export_model(codec=project)` 存一份带时间戳的 `.bbmodel`。任何破坏性改动要先说明代价，不要混在"顺手修一下"里做。
6. **从 `.bbmodel` 取回图集**：`textures[0].source` 是 `data:image/png;base64,...`，解码即可导出 PNG，作为还原点或二次素材。
7. **把原版 PNG 导入 Blockbench 再采样**：`create_texture` 的 `data` 参数接受**文件路径**，可把 `creeper.png` / `phantom.png` 导入，随后在 `risky_eval` 里用 `Texture.all.find(t => t.name === 'phantom.png').img` 直接取像素（脚本沙箱里没有 `fs`，这是唯一的读取通道）。
8. **改动最小化**：只动出问题的那一块，其余区域一律不碰；不要"顺手重建整张图集"。
9. **每步都量化为证据**：改完统计目标区域的色阶数、亮度标准差、杂色像素数（例如"膜面绿色像素 0 个、14 个色阶"），比"看着还行"可靠得多。

## 12.7 图集布局与贴图规划

贴图尺寸不是随手定的，它同时约束 UV 精度、mipmap 表现与显存占用。

- **边长取 16 的倍数**（16 / 32 / 64 / 128 / 256）：与原版方块纹理的像素密度对齐，也便于按 §12.1 的公式心算 UV。
- **边长取 2 的幂**（16 / 32 / 64 / 128 / 256）：现代 GL 对非 2 幂纹理也能正常采样，但 mipmap 生成与某些驱动下的各向异性过滤会退化为无 mipmap；方块风模型一般用 2 的幂。
- **同族部件共用一张图集**：翅膀、身体、尾巴放在同一张 128×128 里，可以只加载一张纹理，也让 UV 坐标好算。多张图集会让渲染层与 tint 逻辑成倍复杂。
- **区域之间留 1–2 px 边距**：相邻两个取料矩形紧贴时，mipmap 的高层采样会把邻居像素混进来（在远处表现为一圈脏边）。留边是解决"远处贴图渗色"的最省事手段。
- **透明区域不要当取料区**：透明像素在 mipmap 下会与相邻色混合出半透明晕边；需要留白就留**完全不透明**的中性色，或干脆不放内容。
- **画布尺寸写进注释**：`v < 64` / `v >= 64` 这类分区判据依赖画布尺寸（如 128×128），换画布后判据全部失效。判据与画布尺寸必须写在一起。

判定手法：把图集按 16×16 或 32×32 网格打印字符图，确认每个取料矩形完整落在同一物件区域内、四周有边距、没有跨越透明区。

## 12.8 多层染色物品：从原版贴图反推分层模板

适用：物品贴图要拆成"外圈 / 内圈 / 厚度"等多层、由代码分别染色（`custom_model_data` tint）的物品。

**手画几何永远对不上**：透视椭圆、沟槽、底面厚度只要有一个像素偏，看着就是"不是原版"。正确做法是**把原版贴图逐像素拆成互不重叠的层掩膜**，不重画任何一个像素。

步骤：

1. 从原版 jar 取目标贴图（`assets/minecraft/textures/item/*.png`），列出全部不透明像素。
2. 按**几何判据**分层，要求"不重不漏"：三层像素数相加 = 原版不透明像素总数，然后用合成图与原版逐像素比对。
3. **每层只保留原版该像素自身的亮度**，按该层**最亮像素**归一化到 255：`v = 255 * lum / peak`。
4. 用各层 peak 对应的灰度当默认 tint，合成结果应与原版逐像素一致（差值仅 ±1 取整）。
5. **换归一化基准必须重算默认 tint**，否则同样的 hex 在新基准下明暗全变。
6. 验证：把三层按 tint 合成回 16×16，与原版逐像素打印 `渲染值 / 原版值` 对照表，差值 > 1 就是判据错了。

一个已定型的数值样例（某多层染色物品，16×16，共 118 个不透明像素，中心孔在 `(7,7)`）：

| 层 | 判据 | 像素数 |
|---|---|---|
| 厚度 `edge` | `y >= 10` 的三行底面 **+ 中心孔 `(7,7)`** | 30 px |
| 内圈 `inner` | 到 `(7,7)` 的距离 ≤ 2.5 且 `y < 10` | 20 px |
| 外圈 `outer` | 其余 | 68 px |

- 30 + 20 + 68 = 118，与不透明像素总数吻合，满足"不重不漏"。
- 中心孔**永远暗**，归到最暗那层最省事；若单独分层，染色时会与厚度层冲突。
- 默认 tint（各层 peak 灰度）：`#515151` / `#7B7B7B` / `#404040`。这个 tint 的语义是"该层最亮的色调"，往下所有明暗都由原版像素给出，**染色即调色**。

归一化基准的选择就是全部（均值、众数两种基准各自会失效）：

| 基准 | 结果 | 失败机理 |
|---|---|---|
| 均值 | 大片像素被压到 255，沟槽全平 | 均值远低于峰值，归一化后亮部全部裁剪 |
| 众数 | 高光全被裁剪，厚度层塌成一块死平色 | 厚度层原版值 64 / 38 / 17，众数只照顾占比最大的那档 |
| 峰值 | 三层都能 1:1 还原 | 亮度分布完整保留，tint 只负责整体色相 |

落点到模型 JSON：每层对应 item model 的一个 `layer`，`tints` 数组按层序写 `{"type": "minecraft:custom_model_data", "index": <层号>}`；层号与代码里写 `custom_model_data` 的顺序必须一致，错位表现为"染错了圈"。层与层之间不能有重叠像素，否则合成时后画的层会覆盖前一层，逐像素比对永远对不上。

## 12.9 骨骼命名、层级与动画

- **骨骼命名用部位语义**（`body` / `head` / `wing_left` / `tail`），不要用编号（`bone1` / `bone2`）。命名是后续 §13.6.1 判定贴图区域的辅助信息，编号没有任何信息量。
- **骨架层级一旦被动画引用就不要改**：bone 的父子关系、pivot 原点决定关键帧的变换空间。改层级或移 pivot，会让已有动画全部错位——且是"看起来还在动、只是位置全偏"的那种错位，很容易被误判成渲染偏移问题。
- **pivot 取关节位置**：翼根、颈部、尾根。pivot 取几何中心会让旋转看起来"绕着身体中段转"，这是模型动画最常见的违和感来源。
- **动画命名必须 `animation.<modid>.<action>`**，且与代码里 `RawAnimation` 的字符串**逐字符一致**（含 `animation.` 前缀）。少一个前缀或大小写不一致，动画静默不播，不会报错。
- **动画时长与 loop 标记写进命名或注释**：`loop: true` 的待机动画与 `once` 的动作动画混用同一个名字，会让"播完就停"变成"无限循环"。
- **新动画由美术在 Blockbench 完成 → 转换脚本产出 → 代码只引用**；代码侧**禁止**临时改动画 json。改了就与美术源文件分叉，下次重导必丢。

判定手法：拿 `.animation.json` 里的 animation 名逐个与代码里 `RawAnimation` 的字面量做**字符串比对**（含前缀、大小写、分隔符），不要靠"应该没错"。数量也要对：代码引用 N 个动画，json 里就得有 N 个同名条目。

## 12.10 `.bbmodel` / `.geo.json` 结构与转换脚本

两个文件格式是同一份几何的两种序列化，转换脚本负责在两者之间搬数据，**它是唯一允许改几何的程序路径**。

`.bbmodel`（工程原件，JSON）：

| 字段 | 内容 |
|---|---|
| `elements` | 几何：`from` / `to` / `origin` / `rotation` / `faces.<面>.uv` / `box_uv` |
| `outliner` | 层级：骨骼（group）的父子关系与顺序 |
| `animations` | 关键帧：animator、channel、keyframe 时间与值 |
| `textures[].source` | 内嵌 base64 PNG（`data:image/png;base64,...`） |

`.geo.json`（运行时几何）：

| 字段 | 内容 |
|---|---|
| `format_version` | 几何格式版本，GeckoLib 5 用其约定的版本号 |
| `minecraft:geometry[].description` | `identifier`（模型 id）、`texture_width` / `texture_height`（贴图尺寸，UV 解析依赖它） |
| `bones[]` | `name` / `parent` / `pivot` / `rotation` / `cubes[]` |
| `cubes[]` | `origin` / `size` / `uv` / `inflate` / `rotation` |

转换脚本必须遵守：

- **Y 轴位移只走脚本参数**（如 `-ModelYShiftPx`），不要在渲染器里塞魔法数（见 [13-entities.md](13-entities.md) §13.4）。脚本产出的位移有明确出处，渲染器里的常数没有。
- **脚本是幂等的**：同一份 `.bbmodel` 跑两次得到逐字节相同的 `.geo.json`（除时间戳外）。非幂等脚本会让"改了没变"和"变了但没提交"都无从判断。
- **脚本输出即资产**：脚本生成的 `*.geo.json` 允许被覆盖；手工改过的 `*.geo.json` 不允许被脚本覆盖前不备份。
- **脚本先做小样验证**：先用一个骨骼跑通（导出 → 重新解析 → 比对 `size` / `origin` / `uv`），再对全模型批量执行。批量跑错公式就是整份资产返工。
- **贴图尺寸写进 `description`**：`texture_width` / `texture_height` 与 `.bbmodel` 画布一致，否则 UV 会被按错误尺寸归一化，表现为整体错位。

## 12.11 Blockbench MCP 操作规范

**铁律**：脚本能力边界先弄清，再写批处理。

- **脚本沙箱没有 `fs` / `require`**：`risky_eval` 里读不了本地文件。要读 `.bbmodel`，用外部 shell 的 `Get-Content -Raw | ConvertFrom-Json`（PowerShell）或等价手段，把数据序列化后送进脚本，或先用 `create_texture` 把图导进来。
- **`.bbmodel` 是 JSON**：`elements`（几何）、`outliner`（层级 / 骨骼父子）、`animations`（关键帧）、`textures[].source`（内嵌 base64 PNG）。要脚本化处理时直接解析这四块，不要靠 GUI 一格格点。
- **改几何 / UV 必须包 undo 事务**：`Undo.initEdit({elements})` → 改 → `Undo.finishEdit()`。
- **每次改完必须 `export_model(codec=project)` 落盘**。Blockbench 窗口被关闭且未落盘 = 模型丢失，这是实测事故，不是理论风险。
- **`capture_screenshot` 可能返回空**：不要把它当成唯一证据；坐标复查、像素统计才是硬证据。截图只用来给人看效果，不用来做判定。
- **采样原版像素的唯一通道**：`create_texture` 的 `data` 接受文件路径 → 导入 PNG → `Texture.all.find(t => t.name === '<file>.png').img` 取像素。沙箱里没有 `fs`，绕不开这一步。
- **改完做坐标复查**：遍历所有部件，比较同轴面坐标，确认无相等项（见 §12.4）。
- **批处理前先小样验证**：先用一个部件跑通（改 UV → 导出 → 重新读回 → 比对坐标），再对全模型批量执行。

## 12.12 资产归属与改动边界

**铁律**：`*.bbmodel`、`*.geo.json`、`*.png`、`*.animation.json` 是美术资产，代码改动不得触碰；转换脚本产出的文件除外，且必须由脚本重新生成。

- 模型对不齐判定箱时，**先怀疑代码**（渲染器 `translate` / `scale`、`EntityType#sized`），不要先去改模型资产。对齐推导见 [13-entities.md](13-entities.md) §13.4。
- 模型高度对齐 hitbox 统一走转换脚本的 YShift 参数（如 `-ModelYShiftPx`），不要在渲染器里塞魔法数。
- 要调层级或 pivot 就重导动画，不要"改一点试试"——动画错位不会立刻显形。
- 交付时资产与代码的修改记录必须分开：资产改动写"哪个部件、哪几个面、改前改后的 uv / 坐标"，代码改动写"哪个渲染器、哪个参数"。

## 12.13 验收与量化证据

美术改动的验收不看"感觉好了"，看四类可复核证据：

| 证据 | 怎么取 | 判据 |
|---|---|---|
| 坐标复查 | 遍历所有部件，按"轴 + 坐标 + 朝向"分组 | 无重叠组 |
| UV 比例 | 逐面算 `uv` 宽高 / 面尺寸 | 全部 = 1（或注明刻意失真） |
| 像素统计 | 目标区色阶数、亮度标准差、杂色像素数 | 色阶 ≥ 2~3，杂色像素 = 0 |
| 实机截图 | 游戏内 F3+B + 多角度 | 模型与判定箱对齐、无闪烁 |

- 三项静态证据（坐标、UV、像素）**必须在实机之前**跑一遍，能挡掉大部分问题，不必每次都开游戏。
- 实机验收要至少两个视角（正侧与俯视）：共面闪烁在正视角常常看不出来，俯视或远距离最明显。
- 截图存档时附一句"这次改了什么、判据是什么"，否则一周后无法判断这张图是新版还是旧版。
- **不要用"看着还行"作为通过条件**：色阶数、杂色像素数、坐标组都是可复现的数字，主观判断无法复现。

## 12.14 症状索引

按"看到的症状"反查根因，比从头读一遍快：

| 症状 | 首要怀疑 | 判据 | 小节 |
|---|---|---|---|
| 某一面被拉成条纹 / 像素被压扁 | 该面 UV 宽高 ≠ 面尺寸 | 逐面算 `uv` 宽高 ÷ 面尺寸 | §12.1 |
| 顶面看起来被压扁 | `up` / `down` 误按 `w × h` 取矩形 | 检查 `up` 的 UV 高度是否等于深度 `d` | §12.1 |
| 整个模型是纯色 | `uv` 填了 0–1 归一化值 | 打印 `uv` 数值，看是否落在 0–画布边长 | §12.2 |
| 交界处闪烁（斜看 / 远处明显） | 同朝向共面 | 按"轴 + 坐标 + 朝向"分组，查重叠 | §12.4 |
| 留了很小间隙仍然闪 | 间隙 < 深度精度 | 量最小间距，是否 ≥ 0.02 | §12.4 |
| 膜面出现规律竖纹 | 源块里有一列杂色，被平铺周期放大 | 字符图检查取料矩形是否全属同一类 | §12.6 |
| 膜面出现彩色杂点 | 取料矩形越界到别的物件区域 | 打印矩形四角与边界像素分类 | §12.5 |
| 远处贴图渗出一圈脏边 | 取料区之间无边距，mipmap 混色 | 检查相邻矩形间距是否 ≥ 1–2 px | §12.7 |
| 动画完全不播 | 动画名与 `RawAnimation` 字符串不一致 | 逐字符比对（含 `animation.` 前缀） | §12.9 |
| 动画在动但位置全偏 | 骨骼层级 / pivot 被改过 | 比对改前的 `outliner` 与 `pivot` | §12.9 |
| 模型"丢了" | 未落盘就关了窗口 | 检查 `*.bbmodel` 的修改时间与内容 | §12.11 |
| 染色圈层错位 | 层号与 `tints.index` 顺序不一致 | 比对层数组顺序与 index | §12.8 |

## 12.15 自检清单

- [ ] 每个面的 UV 矩形宽高 = 该面实际尺寸（1:1），无跨尺寸共用矩形
- [ ] `up` / `down` 用的是宽×深，不是宽×高
- [ ] 模型 `box_uv = false`，六面各自带 `uv` 数组
- [ ] `uv` 填的是像素坐标（0–画布边长），不是 0–1
- [ ] 面的 `rotation` 与宽高匹配，未造成方向性拉伸
- [ ] 无同朝向共面：按"轴 + 坐标 + 朝向"分组复查，无重叠项
- [ ] 外扩量互不相同，任意两面最小间距 ≥ 0.02 模型单位
- [ ] 图集边长取 2 的幂 / 16 的倍数，取料区之间留 1–2 px 边距
- [ ] 贴图源区为纯料：字符图确认矩形内全属同一类像素
- [ ] 平铺块整除目标区，且为镜像平铺（周期 2× 块宽）
- [ ] 目标区保留 ≥ 2~3 个色阶，无纯色块填充
- [ ] 改动已 `export_model(codec=project)` 落盘，且有带时间戳备份
- [ ] 骨骼命名用部位语义，层级与 pivot 未被改动（或已重导动画）
- [ ] 动画名与代码 `RawAnimation` 字符串逐字符一致，数量一致
- [ ] 转换脚本幂等，Y 位移走脚本参数，`texture_width/height` 与画布一致
- [ ] 多层染色物品：三层像素数之和 = 不透明像素总数，合成差值 ≤ 1
- [ ] 归一化基准为峰值，默认 tint 已按该基准重算，层号与 tint index 对齐
- [ ] 坐标 / UV 比例 / 像素统计三项静态证据已跑过，实机截图至少两个视角
- [ ] 代码未触碰任何美术资产文件
