# 15 交付文档规范（写给谁看 · 只写什么 · 绝不写什么）

> 本文件管**模组交付物里的文档**：README、商店页简介、开发 / API 文档、拆出的子文档。
> 不管代码注释（那在 `AGENTS.md` §11「注释卫生」里）。
> 本文件与 `references/` 其余模块同属一个技能包，**没有上位总纲**；结论冲突时以一手证据为准。

标签：**铁律**。违反后果不是"文档不好看"，而是：**读者读到的是 AI 的工作过程而不是模组信息**，或者**文档随每次发版过期、变成维护负担**。

---

## 15.1 先问"读者是谁"

每份文档只服务一类读者。写之前先答一句：**这份东西谁会打开、他打开想解决什么？**

| 读者 | 文档 | 他想解决什么 |
|---|---|---|
| **玩家** | README、商店页简介、游戏内说明 | 这是什么？怎么用？会不会崩？去哪反馈？什么许可证？ |
| **集成者 / 开发者** | API 文档、集成文档、开发者 README | 能做什么？公开接口是什么？最小用法？契约是什么？有什么坑？ |
| **未来的自己 / 协作者** | 项目决策记录（**不是**交付文档） | 为什么这么定？踩过什么？待办什么？ |
| **AI agent** | `AGENTS.md`、`references/` | 必须遵守什么？去哪查细节？ |

> **最常见的错**：把第 3 行和第 4 行的内容写进第 1、2 行的文档里。

---

## 15.2 只写"该读者需要的、关于本模组本身的事实"

### 玩家向（README / 商店页）

**该写**：
- 一句话说明这是什么（英文在前、中文在后）。
- 怎么用（关键操作、快捷键、命令）。
- 注意事项 / 已知限制（例如"仅在服务端生效""需要 Fabric API"）。
- 相关链接（主页、issue、Discord 等**真实可访问**的）。
- 许可证。

**不该写**：
- 版本号（在文件页 / changelog 里，不在这里）。
- 构建命令、工具链、Loader / Java 版本要求（除非是"你必须装 X 才能用"这种玩家需要知道的）。
- 移植备注、API 差异、"回填时注意……"。
- 目录结构、模块划分、类名。

### 开发者向（API / 集成文档）

**该写**：
- 能力清单（这个库 / API 能做什么，一句话一条）。
- 公开接口（类名 + 方法签名 + 参数含义）。
- 最小可运行用法（一段能复制就跑的代码）。
- **契约**：例如"公开 API 只增不改""不保证跨大版本二进制兼容""可选前置缺失时的降级行为"。
- 使用中的坑（会静默失效的写法、必须成对声明的配置）。

**可以写**：
- 集成所需的坐标与环境要求（`implementation '...'`、需要哪个加载器版本）。
- **但不写"本次版本号"** —— 用 `latest.release` 或写版本区间。

### 判断标准

> 逐句问："这句话对**这一类读者**有用吗？" —— 没用就删。

## 15.3 绝不写进交付文档（AI 最常犯，出现即删）

### ① 用户的规范要求 / 提示词本身

```
❌ 本文档遵循"只写本模组实际内容"的原则。
❌ 版本号不用写在这里。
❌ 按项目规范，README 必须中英双语。
```

读者是玩家 / 开发者，不是 AI。**规范要沉淀就写进 `AGENTS.md` 或项目决策记录**，不要出现在交付物里。

### ② 版本号与构建信息

```
❌ 当前版本 1.2.0，基于 NeoForge 21.1.77 构建。
❌ 构建命令：./gradlew build
❌ 需要 Java 21。
```

- 版本号、构建命令、工具链版本**每次发版都会过期**，写进长期文档纯增维护负担。
- 版本号只出现在 `gradle.properties`、changelog、平台文件页。
- **例外**：开发者向文档可以写**集成所需**的环境要求（"需要 Java 21+"），因为那是集成者的前置条件；但**不写"本次版本号"**。

### ③ 移植 / 回填备注

```
❌ 26.1 里 ResourceLocation 改名为 Identifier，回填时注意。
❌ 1.20.1 分支没有 clientInformation()，这里退化成 en_us。
```

跨版本 API 差异、"回填时注意……"、旧版本线怎么改 —— 一律进**项目决策记录**。玩家不需要知道，集成者不需要知道（他只用你这一个版本）。

### ④ 内部过程与决策

```
❌ 本次修复的根因是 ……
❌ 决策 D-07：改用 FG7。
❌ 2026-09-22 实测：……
❌ 注意：AI 不要修改本节。
```

Plan、踩坑过程、决策编号、日期流水、AI 协作规则 —— 全部属于决策记录。

### ⑤ 文档自身的元信息

```
❌ 本文件由 AI 整理。
❌ 后续会持续更新。
❌ 最后更新：2026-09-22
```

除非这是**面向集成者**的 API 变更日志（那种"最后更新"有意义），否则删掉。

### ⑥ 营销式 / AI 式总结句

```
❌ 综上所述，本模组提供了全面而强大的……
❌ 值得注意的是，我们精心设计了……
❌ 为了更好地服务玩家，我们持续优化……
```

直接写事实。

## 15.4 命名与语言结构

### 文件名

- 拆分出的文档：**文件名用英文**（`Animations.md`、`InterfaceAndThemes.md`、`Configuration.md`）。
- **不编号、不排序**（`01-xxx.md` / `02-xxx.md` 是技能包内部的组织方式，不适合交付文档）。
- 大小写与项目其它文档保持一致。

### 语言

- **对外文档与子文档一律英文在前、中文在后**，不混排。
  - 同段落内：`English text. 中文文本。`
  - 或分块：先整段英文，再整段中文。
  - **禁止中文独占**（国际用户是主要受众）。
- 代码示例里的注释语言跟代码注释规则走（库 / 公共 API 用英文）。

### 结构

- README **保持短**：一段介绍 + 一个用法示例 + 链接索引 + 许可证。
- 长内容拆到子目录（如 `docs/`），并在 README 内用**相对链接**做好索引。
- 每个子文档开头一句"本文管什么"，不要写目录树（读者会用搜索）。

### 面向玩家的说明

- 游戏内说明（tooltip、配置界面文案）走**语言键**，不写死在代码里。
- 商店页简介：**单行**，英文在前、中文在后，用 ` | ` 分隔（原因见 [03-metadata.md](03-metadata.md) §3.4 的 `expand` 陷阱）。

## 15.5 交稿自检

写完通读一遍，逐条过：

- [ ] **逐句问**："读者是谁？这句对他有用吗？" —— 有三句以上答不上来就重写。
- [ ] **搜易犯词**，命中即复核是否应移到决策记录：
      `版本`、`1.x.x`、`移植`、`回填`、`本文件`、`AI`、`规范`、`提示词`、`决策`、`实测`、`本次`、`后续`。
- [ ] **搜路径与私有信息**：Windows 盘符路径、Unix 家目录路径、代理端口、实例名、账号名 —— 一个都不许有。
      自查命令（在仓库根跑，只应命中本规范自身的示例行）：
      ```bash
      grep -rnE '([CD]:\\|/Users/|/home/)' . --include='*.md'
      ```
- [ ] **搜占位符**：`<你的`、`TODO`、`XXX` —— 交付前必须全部替换或删掉。
- [ ] **链接全部真实可访问**（点一遍，不要凭印象）。
- [ ] **语言结构**：英文在前、中文在后，没有中文独占的段落。
- [ ] **没有营销句 / AI 总结句**。
- [ ] **README 里的每个相对链接都指向存在的文件**。

## 15.6 一个可直接用的 README 骨架

```markdown
# <Mod Name>

<One sentence: what this mod does.>
<一句话说明这个模组做什么。>

## Features
- <能力 1>
- <能力 2>

## Usage
<最小用法：命令 / 快捷键 / 配置入口>

## Requirements
- Minecraft <版本区间>
- <Loader> <版本区间>
- <可选前置，若有>

## Links
- [Issues](<真实地址>)
- [Source](<真实地址>)

## License
<许可证名，与 LICENSE 文件一致>
```

**注意**：`Requirements` 段写的是**版本区间**（集成者需要知道），不是"本次版本号"。如果这个模组只支持单一版本，写那一个版本即可。

## 15.7 一个可直接用的 API 文档骨架

```markdown
# <Library> API

> One line: what this library provides.
> 一句话：这个库提供什么。

## Capabilities
| 能力 | 入口 |
|---|---|
| <能力> | `<类名>#<方法>` |

## Quick start
```java
// 最小可运行示例
```

## Contract
- 公开 API 只增不改；删除 / 改签名视为破坏性变更。
- <可选前置缺失时的降级行为>
- <必须成对声明的配置>

## Pitfalls
- <会静默失效的写法>
```

**契约段是这个文档最有价值的部分** —— 它决定了集成者能不能安全升级。
